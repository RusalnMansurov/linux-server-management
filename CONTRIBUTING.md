# Contributing

## Development Workflow

1. Update the `develop` branch.
2. Create a new feature branch.
3. Make the required changes.
4. Test the changes.
5. Commit with a meaningful message.
6. Push the feature branch to GitHub.
7. Create a Pull Request into `develop`.
8. Complete code review before merging.

## Branching Strategy

- `main` - stable project versions
- `develop` - integration branch
- `feature/*` - development of new features

## Commit Messages

Commit messages should clearly describe the change.

Examples:

- Add disk usage monitoring script
- Add installation documentation
- Fix service error handling

## Code Review

Changes should be reviewed before they are merged into the project.
